## 1. החזון

מערכת אחת שמחליפה **את כל הכלים שמאמן/ת משתמש/ת בהם היום** — תכנון אימונים, ניהול קבוצות ומתאמנים, נוכחות ומעקב, תקשורת עם ספורטאים והורים, תשלומים וחשבוניות, חנות ותוכן מקצועי — הכל במקום אחד, בלי וואצאפ, אקסל ומחברות.

**עקרונות העל:**

1. **הכל דרך האפליקציה** — תקשורת, תשלומים, תוכניות, דיווחים.
2. **גמיש לכל מאמן** — המערכת לא כופה שיטה, ענף או מבנה; היא מספקת תבניות, עושה את החישובים, והמאמן מחליט.
3. **מגדול לקטן, מדויק ובלי לנחש** — בניית תוכנית מהעונה ומהמרוץ עד לסט הבודד, כשכל נפח, אחוז ואזור מחושבים ומוצגים מול היעד.
4. **כל משתמש רואה רק את שלו** — מאמן ראשי רואה הכול; כל ספורטאי/הורה/מאמן עוזר רואה רק את הרלוונטי אליו.
5. **נתונים אמיתיים בלבד** — שום מספר מוצג למשתמש שאינו נגזר מנתוני המערכת (אין גרפים קשיחים, TSS מזויף או "נוכחות מדומה").
6. **מוכן לכמויות גדולות** — ענן, ריבוי משתמשים, סקאלביליות הגיונית — בתקציב חינמי בשלב הזה.
7. **פשטות מדודה** — כל משתמש פוגש מערכת קטנה לפי תפקידו (progressive disclosure); שלוש "זרימות זהב" (בוקר, בשטח, פרסום שבוע) הן מבחן ההצלחה של המוצר כולו — פירוט ומיצוב השוק ב-[12-market-landscape.md](12-market-landscape.md).

## 4. יעדים שאינם בטווח (Non-Goals) לשלבים הקרובים

- אפליקציה נייטיב (iOS/Android) — PWA רספונסיבי במקום.
- אינטגרציית שעונים — שלב עתידי, אך דגם הנתונים מוכן אליו.
- חנות מסחר אלקטרוני מלאה — מתחילים מטפסי הזמנה.
- AI — שלב אחרון; עד אז: כללים דטרמיניסטיים בלבד.
- מולטי-וואטסאפ/SMS חוצה-מערכת — הכל בתוך האפליקציה.
- **החלפת TrainingPeaks למאמני סיבול יחידניים עמוקים** (TSS/power-first, שנים על ה-PMC) — לא היעד בשלבים הקרובים; מאמן/ת עליית-החוף הוא **הקבוצות** ([12](12-market-landscape.md) §6). יחידנים — הרחבה מבוקרת רק אחרי פריטי התכנון וה-PMC (MON-3) והמייבאים (F3.13).

## 5. המודל העסקי (D19)

| שלב | מודל | פירוט |
|---|---|---|
| **עכשיו** | חינם לכל טננט | המערכת עובדת בכמות קטנה בתקציב 0 ₪ למפתחת ולטננטים (מגבלות התשתית החינמית — [09-architecture.md](09-architecture.md)). |
| **הכנסות ראשונות** | **פרסומות** | מוצגות **רק בפורטל הספורטאי/הורה** (מגזין, דאשבורד הפורטל) — לא בסביבת העבודה של המאמן. **פרסום קונטקסטואלי בלבד, ללא מיקוד אישי לקטינים**, כברירת מחדל ניתן לכיבוי פר-טננט בתשלום עתידי. |
| **עתיד** | **רמות מנויים** למאמנים/מועדונים | מבוסס על גודל (מספר ספורטאים פעילים), תוספות (אינטגרציות, אחסון וידאו, הסרת פרסומות). הדגם נבנה multi-tenant מיום 1 כדי שהמעבר יהיה מתג מסחור, לא שכתוב (ARC-7). |

- **עקרון**: הפיצ'רים המקצועיים של המאמן לעולם לא מוגבלים כדי למכור — המיקרומן מבוסס נפח, הטבות ונוחות.
- פרסום ומדידה: אינטגרציית רשת-פרסום עם הסכמות פרטיות מתאימות — פירוט ב-[09-architecture.md](09-architecture.md) §6.

## 6. מדדי הצלחה (Success Metrics)

| מדד | יעד |
|---|---|
| המאמנת מפסיקה להשתמש בכלים חיצוניים | אקסל/מחברות/וואצאפ לצורכי ניהול = **0** תוך 3 חודשים אצל טננט הפיילוט |
| תיעוד נוכחות | **100%** ממפגשי הקבוצות של טננט הפיילוט מתועדים במערכת |
| תוכניות שבועיות | כל קבוצה פעילה עם תוכנית פורסמת לפחות שבוע קדימה |
| פעילות הורים | ≥ **60%** מההורים פותחים את האפליקציה לפחות פעם בשבוע |
| תשלומים | ≥ **80%** מהחיובים נרשמים/נגבים דרך המערכת |
| גדילה | טננט פיילוט → טננטים נוספים ללא שכתוב; NFR עומד ביעדי [09](09-architecture.md) |
| **Time-to-First-Value** | טננט חדש: מהרשמה ועד **מפגש ראשון מתועד במערכת — פחות מ-30 דקות** עבודה אפקטיבית (ה"טריז" שמאפשר ניסיון במקביל — [12](12-market-landscape.md) §6) |

## 7. אופן הקריאה של המסמכים

- כל דרישה ממוספרת (`USR-1`, `PLAN-3`...) — פיצ'רים ב-[10-roadmap.md](10-roadmap.md) מתייחסים לדרישות שהם מממשים.
- כל מודל מציין **"קיים ב-dev"** (נקודת הפתיחה) ו-**"נדרש"** (דרישות ה-TO-BE), ונשען על פערי ה-AS-IS המתועדים ב-[../specs/08-gaps.md](../specs/08-gaps.md).
- החלטות פתוחות מסומנות ב-**[פתוח]** — ניתן להתחיל לבנות בלעדיהן, והן נסגרות במהלך העבודה.

# כרטיס פיצ'ר — F0.3: Middleware ולידציה + authz

> REQ: ARC-3, ARC-13, DOM-0 · סוגר AS-IS: 4.15, 4.16, 4.17, 4.36

## תרחישים

1. `POST /athletes` בלי `name` → **400** `{error:{code:"VALIDATION_ERROR", details:[...]}}` — לא undefined שנשמר.
2. `PUT /athletes/:id` עם `age: "abc"` → **400** (type mismatch).
3. `DELETE /athletes/:id` על ID לא קיים → **404** (לא 200 שקרי).
4. `DELETE /events/:id` על ID לא קיים → **404**.
5. `POST /events` עם `startTime` בפורמט לא-ISO → **400**.
6. כל הנתיבים כבר דורשים auth (F0.2) — מוודא שגם admin לא עוקף tenant-scoping.
7. Response shape אחיד: `{message: "...", error?: {code, details?}}`.

## מקרי קצה

- Zod `coerce: true` על מספרים — "22" → 22 (ניקוי המחרוזות-מספרים הידני נשאר כגיבוי).
- `schedule[].day` — `z.coerce.number().min(0).max(6)` (מתקן string→number).
- PUT ממזג — validation על הגוף הנכנס, לא על הישות הממוזגת (partial update).
- Event override: `sourceId` + `originalStartTime` חובה (כבר קיים, עובר ל-zod).

## הרשאות

ללא שינוי מ-F0.2 (requireAuth + requireRole). F0.3 מוסיף ולידציה, לא scoping חדש.

## מדידה

- 400 עם `VALIDATION_ERROR` על 5 סוגי בקשות שגויות.
- 404 על DELETE של ID לא קיים (3 routes).
- אפס `undefined` ב-DB אחרי POST עם שדות חסרים.
- Error envelope אחיד על כל ה-routes.

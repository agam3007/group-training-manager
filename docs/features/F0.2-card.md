# כרטיס פיצ'ר — F0.2: Auth + תפקידים

> REQ: USR-1, USR-2, USR-8, USR-9, USR-12, D29 · קשור ל-F0.3 (scoping מלא שלה עוד)
> חלוקת אחריות מול F0.3 (מפורש): F0.2 = מי אתה (authentication) + מודל התפקידים והרשאות-על. F0.3 = מה מותר לך לפי scope (coach על קבוצה מסוימת, ולידציה, טננט-סקופינג מלא).

## תרחישים

1. כמאמנת, אני פותחת את האפליקציה — נשלחת למסך כניסה; נכנסת עם אימייל+סיסמה — ורואה את המערכת כרגיל, על הנתונים שלי מהענן.
2. כל בקשת API ללא token או עם token שפג/מזויף → **401** על כל הנתיבים (חוץ מ-`/health`).
3. הכניסה הראשונה של המשתמשת הראשונה → **Bootstrap**: היא הופכת אוטומטית ל-owner של הטננט (ללא קונפיגורציה ידנית).
4. נכנסתי → `GET /auth/me` מחזיר אותי: שם תצוגה + רשימת תפקידים (איחוד מענקים — USR-12).
5. משתמש שני שנוצר ב-Supabase אך לא קושר לטננט → **403** ("ממתין לאישור ה-owner").
6. כ-owner, אני רואה רשימת משתמשים (`GET /auth/users`) ויכולה להקצות תפקידים (`PUT /auth/users/:id/roles`). משתמש שאינו owner שיקרא לאחד מנתיבים אלה → **403**.
7. התנתקות → חזרה למסך כניסה; refresh של הדף שומר סשן (Supabase persist).
8. סיסמה שגויה → הודעת שגיאה ברורה בטופס.

## מקרי קצה

- ה-owner נמחק/הושבת? app_users לא נמחקים ב-F0.2 (רק is_active=false ב-F0.3+). Bootstrap מותר רק אם אפס משתמשים בטבלה.
- ה-JWT של Supabase: אימות חתימה מול JWKS (SUPABASE_JWKS_URL) + דרישת sub; בדיקת iss/aud תהודק ב-F0.3 (מתועד בקוד).
- טננט: בפיילוט טננט יחיד; ה-user חייב להיות קשור אליו, אחרת 403. סקופינג מלא בטבלאות (per-request tenant) = F0.3.
- CORS פתוח נשאר כרגיל (credentials לא בשימוש — Bearer בלבד).
- Email confirm: המשתמשת נוצרת מול confirmed=true בדאשבורד (הנחיות למשתמשת).

## הרשאות

- כל הנתיבים (חוץ מ-/health): דורשים JWT תקף + משתמש app פעיל בטננט.
- `/auth/users*`: owner בלבד (requireRole). שאר הנתיבים: כל חבר טננט (ה-scoping העדין מגיע ב-F0.3/F1.x).
- סיסמאות חיות אך ורק ב-Supabase Auth — לעולם לא ב-DB שלנו.

## i18n/RTL

מסך הכניסה: מחרוזות באנגלית לעת עתה (עקבי עם שאר ה-UI; F0.4 היה pilot-עברית — יתורגם אז; ההחלטה מתועדת כחוב מתוכנן).

## מדידה

- 401 על כל 17 ה-routes ללא token (סמוק-טסט).
- כניסה של ה-owner → הכל 200 כמו קודם (נתונים זהים).
- 403 למשתמש לא-מקושר; 403 ללא-owner על /auth/users.

## סקופ מודע

- הזמנות/מיילים, איפוס סיסמה (Supabase מספק עמודים מוכנים — נשלב ב-F0.3+/שלב 2).
- Guardianship/פורטל הורה — שלב 2 (D28).
- Per-route role-scoping מלא — F0.3.
- יצירת משתמש דרך ה-UI — המשתמשת נוצרת בדאשבורד Supabase (Authentication → Users), כרגע.

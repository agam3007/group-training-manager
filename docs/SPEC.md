## 1. מהי המערכת

**Group Training Manager** היא אפליקציית ווב לניהול אימוני ספורט קבוצתיים ואישיים, המיועדת למאמן/ת (משתמש יחיד, ללא הרשאות). המערכת מנוהלת:

- **קבוצות אימון** — פרופיל, חברות ספורטאים (טבלת צירוף), סדר אימונים שבועי שמניע את הלוח, יעדים והערות.
- **ספורטאים** — פרופיל אישי, אנשי קשר, בריאות/פציעות, מבחני כושר (Tests), אזורי אימון (Zones), שיאים אישיים (PBs), יעדים/מרוצים (Goals) עם תוכנית מרוץ וביקורת, והערות.
- **דאשבורד** — ציר אירועי היום (מאוחד מהשרת), סטטיסטיקות, **רישום נוכחות קבוצתי** ו**רשימת סיכון** (ספורטאים שצריך לדבר איתם) עם זרימת check-in.
- **לוח שבועי** (Calendar) — אירועים ממוזגים משרת (שיוכי אימונים, סדרי קבוצות וירטואליים, דריסות ואירועים ידניים), ספריית אימונים עם תיקיות, בונה אימון מבוסס-טקסט עם פרסר, ומחשבון עומס.
- **תוכניות אימון** (מודול חדש) — וויזארד לבניית מקרו-מחזור (פאזות מזו, שבועות מתוכננים עם יעדי נפח/אזורים, אירועי מפתח), לוח תוכנית שבועי לתכנון אימונים, והחלת התוכנית על ספורטאי/קבוצה.

## 2. ארכיטקטורה בקצרה

```
┌─────────────────────────┐        HTTP (REST/JSON)        ┌──────────────────────────┐
│  Client (React SPA)     │  ────────────────────────────► │  Server (Express)        │
│  Vite · React 19 · TS   │ ◄────────────────────────────  │  Express 5 · TS          │
│  http://localhost:5173  │   base URL מ-VITE_API_URL       │  http://localhost:3001   │
└───────────┬─────────────┘                                └────────────┬─────────────┘
            │                                                                        │
  shared/types (מקור אמת אחד לטיפוסי דומיין — מיובא בשני הצדדים)                  │
                                                                        קריאה/כתיבה של קובץ שלם
                                                                        ▼
                                                          server/src/db/database.json
                                                          (15 אוספים — עדיין ללא DB אמיתי)
```

- אין הרשאות/אימות (Auth) — השרת פתוח לחלוטין (CORS מאופשר לכולם).
- השרת גדל מ-4 ל-**17 מודולי routes + 3 שירותים** (נוכחות, דאשבורד, הערות).
- אין סטייט גלובלי בלקוח; אין DB אמיתי, נעילות או ולידציה כללית.
- פירוט מלא: [specs/01-architecture.md](specs/01-architecture.md)

## 3. מודולים פונקציונליים ומצבם

| מודול | מסלול | מצב קיים |
|---|---|---|
| Dashboard | `/` | **עובד ומחובר לשרת** — אירועי היום, נוכחות קבוצתית, רשימת סיכון ו-resolve; מחווני AdminTodo/QuickInsight קיימים אך מושבתים ולא מחוברים |
| לוח שבועי | `/schedule` (+`/athlete/:id`) | **עובד מול השרת** — יצירה/גרירה/עריכה נשמרות; חריגות: ביטול מופע חוזר שבור, מסלול הקבוצה מתעלם מהפרמטר, יום ראשון שולף שבוע קודם |
| קבוצות | `/groups` , `/groups/:id` | **עובד** — יצירה, עמוד פרטים מלא (עריכה, סדרים, חברים, יעדים, הערות); סטטיסטיקות הקבוצה מדומות |
| ספורטאים | `/athletes` , `/athletes/:id` | עובד — יצירה מהירה ופרופיל עשיר; Analytics מבוסס נתונים אמיתיים (שיוכים+ציות) |
| מנוע אזורים ומבחנים | (בתוך פרטי ספורטאי) | עובד; נוספו פריסטים ומצב custom מורחב; נוסחת CSS ושמירת Pace עדיין באגיות; gym "coming soon" |
| תוכניות אימון | `/training-plans(/calendar)` | **מודול חדש** — וויזארד ולוח תוכנית עובדים במצב מבוסס-שבועות; מבוסס-תאריכים שבור בתצוגה; placeholders זורקים את קלט המשתמש |

## 5. עקרונות התיעוד

- **AS-IS בלבד** — כל קובץ מתאר מה קיים, גם אם שבור או חלקי. פערים לא מתוקנים במסמכים אלא מרוכזים ב-[08-gaps.md](specs/08-gaps.md).
- שמות שדות, נתיבים וקומפוננטות נשארים באנגלית כפי שהם בקוד.
- מקור האמת: קוד המקור בלבד (אין תיעוד קודם בפרויקט).

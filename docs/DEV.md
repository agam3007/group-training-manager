# DEV.md — נקודת הכניסה למפתח/ת

> המסמך היחיד שצריך לקרוא ביום הראשון. שאר התיעוד מתואר לפי קישורים.

## 1. הרצה מקומית

| צד | פקודה | כתובת |
|---|---|---|
| שרת | `cd server && npm run dev` | http://localhost:3001 (Express 5 + TS, ts-node-dev) |
| לקוח | `cd client && npm run dev` | http://localhost:5173 (Vite) |

- **משתני סביבה**: לקוח — `VITE_API_URL` (ברירת מחדל `http://localhost:3001`); שרת — `PORT`.
- ⚠️ **מצב נוכחי**: `tsc -b` בלקוח **נכשל** (באג AS-IS 4.32). עד לתיקון — `npm run dev` עובד כי Vite לא מריץ בדיקת טיפוסים; `npm run build` לא. תיקון זה הוא המשימה הראשונה (F0.5).
- **מסד נתונים נוכחי**: `server/src/db/database.json` — קריאה/כתיבה של קובץ שלם בכל בקשה. מוחלף ב-Postgres ב-F0.1; עד אז — לא לשכתב את הלוגיקה סביבו, רק להבין אותה.

## 3. כללי העבודה

- **הפיצ'ר הבא תמיד מה-roadmap**, לפי הסדר המומלץ. מעבר בין שלבים — רק אחרי השער העסקי ([13 §8](to-be/13-business-plan.md)).
- **לפני מימוש** — כרטיס לפי נוהל AC ([11 §4](to-be/11-appendix.md)): תרחישים בשפת משתמש, מקרי קצה, מטריצת הרשאות, RTL.
- **DoD** ([10 §0](to-be/10-roadmap.md)): בדיקות לפי [11 §6](to-be/11-appendix.md) (unit לחישובים, integration ל-authz, **E2E לזרימות הזהב**), וזרימות הזהב לא נשברות.
- **גיט**: ענף פיצ'ר מ-`dev`, PR קטן, CI (F0.6) חוסם על בנייה ירוקה + בדיקות.
- **כל מחרוזת חדשה** — דרך מפתחות i18n (עברית+אנגלית, RTL/LTR — ARC-4).
- **כל תאריך** — לפי ARC-9: טננט = אזור זמן אחד, שמירה לוקאלית, **לעולם לא מערבבים UTC** במופעים.
- **כל endpoint חדש**: ולידציה + authz לפי תפקיד + tenant-scoping (ARC-3) + מעטפת השגיאה ו-pagination (ARC-13/ARC-8).

## 4. המשימה הראשונה שלך — F0.5 (בנייה ירוקה)

> **F0.5 הושלם (13/10/2026)** — הבנייה ירוקה בשני הצדדים, הקוד המת נמחק, ה-env תוקן.
> **F0.1 הושלם (13/10/2026)** — Postgres חי. ה-DB בענן: Supabase (eu-central-1). `npm run migrate` + `npm run backup` ב-`server/`.
> **F0.2 (Auth)** — הכניסה דורשת Supabase Auth. המשתמשת הראשונה שנכנסת = ה-owner של הטננט אוטומטית. משתמשים נוספים נוצרים ב-Supabase Dashboard → Authentication → Users, ומקבלים תפקידים דרך `PUT /auth/users/:id/roles` (owner only). הלקוח מצרף את ה-token בעצמו (`src/auth/attachAuth.ts`).
>
> להרצה מלאה: `server/` → `npm run dev`, `client/` → `npm run dev` → נפתח ב-`http://localhost:5173` → מסך כניסה.

## 6. "איך X אמור לעבוד?" — איפה התשובה

כל דרישה מוגדרת בדיוק במקום אחד לפי קידומתה: `USR-` → 01 (משתמשים/הרשאות) · `DOM-` → 02 (ישויות) · `PLAN-` → 03 (תכנון) · `SES-` → 04 (מפגשים/נוכחות/שיבוץ) · `MON-` → 05 (מעקב) · `COM-` → 06 (תקשורת) · `PAY-` → 07 (תשלומים) · `SHOP/CONT-` → 08 · `ARC-` → 09 (תשתית/NFR). הטבלה המלאה — [11 §5](to-be/11-appendix.md).
